# FastAPI and Neon Backend

The backend is a synchronous FastAPI service using SQLAlchemy 2, Psycopg 3, Pydantic Settings, Argon2 password hashes, and short-lived JWT bearer tokens. It is configured for Neon PostgreSQL with TLS. SQLite is used only for isolated automated tests.

The AI Copilot has a separate, read-only analytics/service layer. It defaults to deterministic, evidence-backed rules (`AI_PROVIDER=rules`) and does not require an external AI key. To enable an OpenAI-compatible provider, set `AI_PROVIDER=openai-compatible`, `AI_MODEL`, and `AI_API_KEY` in the private `backend/.env`. Optionally set `AI_BASE_URL` and `AI_TIMEOUT_SECONDS`. Never put the provider key in a `VITE_` variable or frontend file.

## Install and configure

1. Create a Neon project and database. Copy the PostgreSQL connection string from Neon and keep it private.
2. From this directory, create and activate a virtual environment, then install dependencies:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   Copy-Item .env.example .env
   ```

3. Edit `.env` locally. Set `DATABASE_URL` to the Neon connection URL (`postgresql://...`; the app selects Psycopg 3 and adds no credentials to the frontend). Include `?sslmode=require` as provided by Neon. Generate a signing key locally, for example with `python -c "import secrets; print(secrets.token_urlsafe(48))"`, and put the result in `JWT_SECRET_KEY`. Never commit `.env` or send the signing key to Vite.
4. Set `CORS_ORIGINS` to a JSON array containing the exact frontend origins, for example `CORS_ORIGINS=["http://localhost:5173"]`. Add the Vite port shown in its terminal if it selected another port.
5. Create/update the schema and start the API:

   ```powershell
   python -m alembic upgrade head
   python seed.py
   python -m uvicorn app.main:app --reload --port 8000
   ```

`seed.py` prompts for the seed merchant email and password if `SEED_MERCHANT_EMAIL` and `SEED_MERCHANT_PASSWORD` are not set. The password prompt is not echoed. Seeding is idempotent by merchant email. A seed password is never stored in source.

## Schema

| Table | Purpose and important relationships |
| --- | --- |
| `merchants` | Account, unique email, Argon2 password hash, business name, creation time. |
| `products` | Merchant-owned grocery catalog; unique `(merchant_id, sku)`, numeric selling/cost prices, nonnegative stock and per-item low-stock threshold. |
| `transactions` | Merchant-owned recorded sale/order, payment method, total, optional non-PII customer reference, timestamp. |
| `transaction_items` | One or more line items per transaction; stores name/SKU/price snapshots so history survives product edits/deletion. |
| `inventory_movements` | Merchant-owned stock delta, type, reason, timestamp, and product-name snapshot; product reference becomes null on product deletion. |
| `campaigns` | Merchant-owned campaign examples and status. |

Amounts use `NUMERIC(12,2)`. UUIDs are generated by the application. Foreign keys and check constraints protect referential integrity and nonnegative stock/prices.

## Authentication and tenant access

Register with a business name, email, and password of at least eight characters. Passwords are Argon2-hashed. Login returns a 60-minute HS256 JWT. Send it as `Authorization: Bearer <accessToken>`. All data endpoints require a valid token and include `merchant_id` in their queries; another merchant's product ID resolves as 404. The browser stores the access token in `sessionStorage`, not database credentials. There is no payment-gateway integration.

Sale creation locks the merchant's product rows with `SELECT ... FOR UPDATE`, checks all requested stock, then inserts transaction/item rows, deducts stock, and creates movement records in one SQLAlchemy transaction. Insufficient stock returns 409 and leaves all rows unchanged. Restock, count, product, and movement writes are likewise committed together.

## API overview

All JSON fields use camelCase. Interactive docs are available at `/docs`; OpenAPI JSON is `/openapi.json`.

| Method | Endpoint | Description | Auth |
| --- | --- | --- | --- |
| `POST` | `/api/v1/auth/register` | Create a merchant and return a token. Body: `businessName`, `email`, `password`. | No |
| `POST` | `/api/v1/auth/login` | Verify credentials and return a token. Body: `email`, `password`. | No |
| `GET` | `/api/v1/auth/me` | Current merchant profile. | Yes |
| `GET` | `/api/v1/dashboard?period=7d` | Period-scoped sales metrics, comparison, grouped series, top five products, current inventory alerts, and insights. `period` supports `7d` (default), `30d`, and `12m`. Aggregates and rankings run in PostgreSQL. | Yes |
| `GET` | `/api/v1/ai-copilot/context` | Merchant-scoped summarized sales, product, inventory, customer-reference, and campaign context. Does not return raw transactions. | Yes |
| `POST` | `/api/v1/ai-copilot/analyze` | Analyze summarized context and return evidence-linked insights, opportunities, and confirmation-required recommendations. Optional body: `{"question":"What should I restock?"}`. | Yes |
| `GET` | `/api/v1/ai-copilot/recommendations` | Convert detected opportunities into practical, approval-required merchant actions with supporting numbers, qualitative expected impact, and confidence. | Yes |
| `POST` | `/api/v1/ai-copilot/chat` or `/api/ai-copilot/chat` | Conversational assistant that answers from merchant-scoped retrieved analytics. Body: `{"message":"How is my business doing this week?","conversation":[]}`. | Yes |
| `GET`, `POST` | `/api/v1/products` | List/create owned products. | Yes |
| `GET`, `PATCH`, `DELETE` | `/api/v1/products/{productId}` | Read/update/delete one owned product. | Yes |
| `GET` | `/api/v1/transactions?limit=100` | List recent sales with line items (default 100, max 1,000). Add `today=true` to return only the authenticated merchant's current Asia/Kolkata day, newest first. Dashboard analytics are aggregated separately in PostgreSQL. | Yes |
| `POST` | `/api/v1/transactions` | Record a sale and deduct stock atomically. | Yes |
| `GET` | `/api/v1/inventory` | Product stock and movement history. | Yes |
| `POST` | `/api/v1/inventory/products/{productId}/restock` | Add stock and record reason. | Yes |
| `POST` | `/api/v1/inventory/products/{productId}/count` | Set counted on-hand quantity and record delta/reason. | Yes |
| `PATCH` | `/api/v1/inventory/products/{productId}/threshold` | Update low-stock threshold. | Yes |
| `GET` | `/api/v1/campaigns` | List the merchant's campaigns. | Yes |

Common errors: `401` missing/invalid token, `404` resource not owned/found, `409` duplicate SKU or insufficient stock, and `422` invalid request fields.

## API examples

Use `curl.exe` in PowerShell (replace values locally; never paste secrets into source control):

```powershell
curl.exe -X POST http://localhost:8000/api/v1/auth/register -H "Content-Type: application/json" -d '{"businessName":"Fresh Mart","email":"owner@example.com","password":"change-this-password"}'
```

Use the returned `accessToken` for authenticated requests:

```powershell
curl.exe http://localhost:8000/api/v1/dashboard -H "Authorization: Bearer TOKEN"
curl.exe -X POST http://localhost:8000/api/v1/transactions -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" -d '{"items":[{"productId":"PRODUCT_UUID","quantity":2}],"paymentMethod":"UPI","customerReference":"loyalty-104"}'
curl.exe -X POST http://localhost:8000/api/v1/inventory/products/PRODUCT_UUID/restock -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" -d '{"quantity":12,"reason":"Supplier delivery"}'
```

For manual stock counts, `POST /api/v1/inventory/products/{productId}/count` accepts `{"stockQuantity": 8, "reason": "Physical count"}`. Product creation accepts `name`, `category`, `sku`, `unitPrice`, `costPrice`, `stockQuantity`, and `lowStockThreshold`.

## Sample data

`seed.py` creates the Mehta Fresh Mart development account. For the existing Balaji Super Market account, `python seed_grocery_dataset.py --dry-run` validates a synthetic dataset without committing; `python seed_grocery_dataset.py` then writes it transactionally. Defaults are 120 products across 12 grocery categories, 1,000 multi-item sales, 180 tagged customer references, weekly restocks, count/expiry adjustments, and four campaigns, for the last 30 calendar days. The generated sample rows are marked `SYNTHETIC` in customer references, campaign names/reach, and inventory reasons.

The comprehensive seeder removes only the earlier `sample-month:` synthetic transactions and `Sample month` movements. It refuses to proceed if it finds untagged/real sales, ambiguous merchant names, or unreconciled existing inventory. Product additions use stable synthetic SKUs and IDs, repeat runs are detected by a date-batch marker, and all writes (including cleanup of the old tagged sample) commit or roll back together. It preserves the merchant account, login, existing non-sample records, and product details. Unit sizes are encoded in product names because the current Product schema has no unit column. The schema has no Customer, Supplier/Purchase, tax, or discount entities; customer references and campaign/movement fields are used instead, with no new tables introduced.

## Migrations

The initial revision is `alembic/versions/6b13eabab60b_initial_schema.py`. Run `python -m alembic upgrade head` for deploys. For model changes, create a revision with `python -m alembic revision --autogenerate -m "describe change"`, review the generated SQL and constraints, test upgrade/downgrade on a disposable database, then apply with `upgrade head`. Do not modify a migration that has already been applied in a shared environment; create a forward migration instead. Back up production data before migrations. `downgrade -1` is for controlled rollback only and can drop data.

## Tests

```powershell
python -m pytest
```

The suite creates isolated in-memory SQLite tables and checks auth-required access, cross-merchant isolation, successful sales, rejected oversells, and inventory movement consistency. It does not require or contact Neon.
